# Transformer / GPT 完整流程总结

假设用户输入一句话：

```text
苹果发布了新款
```

模型最终想生成：

```text
手机
```

整个过程可以分成 4 大阶段：

```text
文字
↓
1. Tokenizer
↓
2. Embedding
↓
3. 多层 Transformer
   ├─ Attention
   ├─ Residual
   ├─ MLP
   └─ Norm
↓
4. 词表预测
↓
生成下一个 token
↓
把新 token 加入上下文
↓
继续下一轮
```

---

# 一、Tokenizer：把文字变成模型认识的 token

输入：

```text
苹果发布了新款
```

Tokenizer 可能切成类似：

```text
[苹果] [发布] [了] [新款]
```

实际切法取决于模型自己的 tokenizer。

每个 token 会变成一个整数 ID：

```text
苹果 → 3812
发布 → 7281
了   → 193
新款 → 12503
```

所以模型真正接收到的不是文字：

```text
苹果发布了新款
```

而是：

```text
[3812, 7281, 193, 12503]
```

现实意义：

> Tokenizer 是“文字世界”和“数学世界”之间的入口。

---

# 二、Embedding：把 token ID 变成向量

模型不能直接理解：

```text
3812
```

所以会去自己的 Embedding 表里查：

```text
3812 → [0.21, -0.73, 1.12, ...]
```

例如：

```text
苹果 → X苹果
发布 → X发布
了   → X了
新款 → X新款
```

每个 token 变成一个高维向量。

比如假设 hidden size 是 4096：

```text
苹果 → 4096维向量
发布 → 4096维向量
...
```

这个初始向量还可以理解成：

> 模型对“这个 token 本身”的初始表示。

这时候它还没有真正吸收上下文。

例如：

```text
苹果
```

此时还不能完全确定：

```text
苹果公司？
苹果水果？
```

---

# 三、位置信息

Transformer 本身并不知道：

```text
苹果 发布
```

和：

```text
发布 苹果
```

有什么顺序区别。

所以还需要位置信息。

现代模型通常会通过类似 RoPE 的方式，把位置影响施加到 Attention 的 Q/K 上。

所以模型不仅知道：

```text
这是“苹果”
```

还知道：

```text
这个“苹果”出现在第几个位置
```

---

# 四、进入第一层 Transformer

假设这一层收到：

```text
X苹果
X发布
X了
X新款
```

一层 Transformer 核心可以粗略理解成：

```text
X
↓
Norm
↓
Attention
↓
Residual
↓
Norm
↓
MLP
↓
Residual
↓
下一层
```

---

# 五、Attention 第一步：生成 Q / K / V

以某一层的某一个 head 为例。

这一层有训练好的矩阵：

```text
WQ
WK
WV
```

每个 token 都会计算：

```text
Q = X × WQ
K = X × WK
V = X × WV
```

例如：

```text
苹果：
Q苹果
K苹果
V苹果

发布：
Q发布
K发布
V发布

了：
Q了
K了
V了

新款：
Q新款
K新款
V新款
```

现实意义：

```text
Q
= 我现在想找什么信息？

K
= 别人应该通过什么特征找到我？

V
= 如果别人关注我，我真正提供什么信息？
```

注意：

这些不是人工规定的。

模型训练过程中自己学出了这样的功能分工。

---

# 六、Q 和 K 做点积：决定“该看谁”

假设当前处理的是：

```text
新款
```

它拿：

```text
Q新款
```

去和前面所有可见 token 的 K 做点积：

```text
Q新款 · K苹果
Q新款 · K发布
Q新款 · K了
Q新款 · K新款
```

得到：

```text
苹果   → 3.1
发布   → 5.8
了     → 0.4
新款   → 2.7
```

现实意义：

> 当前 token 和这些历史 token 的“匹配程度”。

注意 GPT 有 causal mask。

所以：

```text
第 i 个 token
```

只能看：

```text
自己 + 左边
```

不能偷看未来。

---

# 七、Softmax：把匹配分变成关注比例

刚才：

```text
苹果   3.1
发布   5.8
了     0.4
新款   2.7
```

经过 Softmax，可能变成：

```text
苹果   20%
发布   60%
了      3%
新款   17%
```

现实意义：

> 当前 token 应该把多少注意力分配给每个历史 token。

---

# 八、权重 × V：真正把信息拿回来

前面 Q·K 只是决定：

```text
“该看谁”
```

真正的信息来自 V。

例如：

```text
0.20 × V苹果
+
0.60 × V发布
+
0.03 × V了
+
0.17 × V新款
```

得到：

```text
这个 head 的输出
```

现实意义：

> 按照重要程度，从其他 token 那里把信息拿回来。

所以一句最重要的话：

```text
Q/K 决定看谁
V 决定拿什么
```

---

# 九、Multi-Head：同时从多个角度看

真实模型不是只有一个 head。

假设有很多 head：

```text
Head1
Head2
Head3
...
```

它们都会独立计算 Attention。

可以粗略理解成：

```text
Head1：更关注语法关系
Head2：更关注实体关系
Head3：更关注局部搭配
Head4：更关注长距离关系
...
```

实际不会严格“一头一个功能”，只是帮助理解。

所有 head 的结果最后会：

```text
Concat
```

拼起来。

---

# 十、WO：把多个 head 的结果整合回主干

多个 head 拼起来后，会乘：

```text
WO
```

得到：

```text
ΔAttention
```

现实意义：

> 把各个 head 的“工作空间结果”，整合成主干 hidden state 可以接收的修改量。

注意不是：

```text
恢复原来的 X
```

而是：

```text
生成一个适合加回 X 的修正量
```

---

# 十一、Residual：不要推倒重来，只修改

然后：

```text
X_new = X + ΔAttention
```

现实意义：

> 原来的理解保留，再加上从上下文里新拿到的信息。

例如：

原来：

```text
苹果
≈ 公司 / 水果都有可能
```

经过上下文：

```text
发布
新款
```

Attention 后可能开始更偏向：

```text
苹果公司
```

---

# 十二、MLP：把拿回来的信息自己“消化”

Attention 更像：

> 去别人那里拿信息。

MLP 更像：

> 自己内部做进一步加工。

典型结构：

```text
X
↓
线性层 W1
↓
非线性激活
↓
线性层 W2
↓
ΔMLP
```

现实意义：

```text
W1
→ 检测很多潜在模式

激活函数
→ 决定哪些模式应该被激活

W2
→ 把这些模式重新组合成主干修改量
```

比如当前上下文已经是：

```text
苹果 + 发布 + 新款
```

MLP 可能强化：

```text
科技公司
产品发布
消费电子
```

压低：

```text
水果
食物
```

然后：

```text
X_new = X + ΔMLP
```

---

# 十三、为什么必须有非线性？

如果只有：

```text
X × W1 × W2
```

那么：

```text
W1 × W2
```

完全可以合成一个矩阵：

```text
W
```

于是仍然只是：

```text
X × W
```

所以两层线性层没有本质提升。

加入：

```text
激活函数
```

之后：

```text
activation(XW1)W2
```

就不能简单合并。

模型因此可以表达：

```text
门槛
条件
组合模式
复杂关系
```

现实意义：

> 线性层负责重新组合特征，非线性让模型产生复杂判断能力。

---

# 十四、Norm：防止数值越来越乱

模型有几十层甚至更多。

如果一直：

```text
X + Δ1 + Δ2 + Δ3...
```

数值尺度可能越来越难控制。

所以会做 Norm。

现实意义：

> 把向量数值尺度整理到稳定范围。

现代模型经常使用：

```text
RMSNorm
```

例如：

```text
X
↓
Norm
↓
Attention
↓
+ X
```

也就是 Pre-Norm。

---

# 十五、进入第二层、第三层……

第一层结束以后：

```text
苹果
```

已经不是最初那个纯 embedding 了。

它可能已经吸收：

```text
发布
新款
```

的信息。

于是第二层的输入：

```text
X苹果(第二层)
```

已经是：

```text
苹果本身
+
第一层上下文
+
第一层 MLP 加工
```

第二层再重新生成：

```text
Q2
K2
V2
```

继续 Attention。

所以：

```text
第1层
→ 初步建立上下文

第2层
→ 在已有上下文上继续理解

第3层
→ 更复杂的关系

...

最后一层
→ 高度上下文化
```

---

# 十六、Hidden State 到底是什么？

Hidden state 就是：

> 某个 token 在模型当前这一层里的“内部理解向量”。

比如：

```text
“苹果”
```

不同层：

```text
Embedding阶段：
苹果本身

第1层：
苹果 + 周围局部信息

第10层：
更明确地接近苹果公司

最后层：
已经结合整句话，形成高度上下文化表示
```

但是它始终是一个高维向量。

---

# 十七、最终怎么预测下一个 token？

假设输入：

```text
苹果发布了新款
```

最后一个位置“新款”的最终 hidden state：

```text
H
```

代表：

> 模型对整个前缀“苹果发布了新款”的当前理解。

然后用：

```text
W_vocab
```

把 H 从 hidden space 投影到词表空间：

```text
H × W_vocab
```

---

# 十八、词表空间

假设词表只有：

```text
苹果
手机
电脑
产品
。
```

那么：

```text
H × W_vocab
```

得到：

```text
苹果 → 1.1
手机 → 8.7
电脑 → 4.2
产品 → 3.8
。   → 0.7
```

这些叫原始分数。

你可以简单理解成：

> 模型给词表里每个 token 打了一次分。

---

# 十九、Softmax：变成概率

例如：

```text
手机 8.7
电脑 4.2
产品 3.8
...
```

经过 Softmax：

```text
手机 75%
电脑 10%
产品 8%
其他 7%
```

现实意义：

> 把词表候选分数变成概率分布。

---

# 二十、Sampling：真正选一个 token

可以直接选最高概率：

```text
argmax
```

也可以采样：

```text
sampling
```

并配合：

```text
temperature
top-k
top-p
```

例如最终选中：

```text
手机
```

于是：

```text
苹果发布了新款
```

变成：

```text
苹果发布了新款手机
```

---

# 二十一、然后怎么办？

非常重要：

> 不会直接凭刚才的概率顺便把后面的字全生成出来。

而是：

```text
苹果发布了新款手机
↓
重新经过 Transformer
↓
重新 Attention
↓
重新 MLP
↓
重新得到最终 hidden state
↓
重新给整个词表打分
↓
预测下一个 token
```

例如：

```text
。
```

然后再继续。

所以 GPT 本质是：

```text
生成一个 token
↓
加入上下文
↓
重新计算
↓
生成下一个 token
↓
加入上下文
↓
重新计算
↓
...
```

---

# 二十二、为什么不会越来越慢得离谱？KV Cache

假设已经有：

```text
苹果 发布 了 新款 手机
```

前面所有 token 在每一层的：

```text
K
V
```

已经计算过了。

生成下一个 token 时，不需要把它们重新计算。

缓存：

```text
K苹果 V苹果
K发布 V发布
K了   V了
K新款 V新款
K手机 V手机
```

这就是：

```text
KV Cache
```

新 token 只需要计算自己的：

```text
Q_new
K_new
V_new
```

然后：

```text
Q_new
↓
和历史 K 匹配
↓
从历史 V 拿信息
```

为什么不缓存 Q？

因为：

```text
历史 Q
```

未来基本不会再被使用。

但是：

```text
历史 K/V
```

未来每个新 token 都要用。

所以叫：

```text
KV Cache
```

而不是：

```text
QKV Cache
```

---

# 二十三、Prefix Cache：为什么相同前缀可以复用？

假设：

```text
请求1：
A + B

请求2：
A + C
```

由于 GPT 是 causal attention：

```text
A
```

计算时根本看不到后面的：

```text
B / C
```

所以：

```text
A+B
```

和：

```text
A+C
```

里面 A 部分所有层的 KV 都完全一样。

因此可以：

```text
第一次：
算A → 缓存A

第二次：
A直接命中缓存
只计算C
```

所以缓存粒度不是：

```text
某个单独 token
```

而是：

> 从序列开头到当前位置为止的完整相同前缀。

---

# 二十四、为什么 DeepSeek MLA 可以省 KV Cache？

普通 Attention：

```text
每个 token
→ 缓存完整 K
→ 缓存完整 V
```

MLA 的核心：

```text
X
↓
压缩矩阵
↓
更小 latent C
↓
只缓存 C
```

然后需要时：

```text
C
↓
训练好的投影
↓
K/V相关信息
```

甚至可以通过矩阵吸收，让很多计算直接在 latent 空间完成。

核心思想：

> 不缓存完整 K/V，而缓存能代表它们主要信息的压缩表示。

所以：

```text
KV Cache 更小
↓
显存占用更低
↓
更高并发
↓
更长上下文
```

---

# 二十五、大规模并发为什么 GPU 扛得住？

因为不是：

```text
一个用户算完
再算另一个
```

而是 batching。

例如：

```text
用户A 当前 token
用户B 当前 token
用户C 当前 token
...
```

组成：

```text
X_batch
```

一起做：

```text
X_batch × WQ
X_batch × WK
X_batch × WV
```

GPU 非常擅长这种大矩阵运算。

所以核心思想是：

> GPU 不怕算多，GPU 怕算得零碎。

在线推理会配合：

```text
Continuous Batching
KV Cache
多 GPU
模型副本
Tensor Parallel
Pipeline Parallel
```

共同提高吞吐。
