# 推理吞吐优化

## 定义

推理吞吐优化关注的是：在模型结构不变或近似不变的前提下，如何让在线服务在延迟、并发、显存和成本之间取得更好的平衡。它不仅是“让单次推理更快”，更是“让 GPU 在真实多用户场景下更高效地工作”。

## 这份材料涉及的几个关键手段

- [[llm-agent/concepts/KV Cache与Prefix Cache|KV Cache 与 Prefix Cache]]：减少历史上下文的重复计算。
- batching：把多个请求的当前 token 合并成更大的矩阵计算。
- continuous batching：持续把新到达请求并入批次，提升设备利用率。
- 多 GPU / Tensor Parallel / Pipeline Parallel：把模型或计算图拆到多块设备上，缓解单卡容量和算力瓶颈。
- 压缩缓存表示：例如 MLA 类思路，减少 K/V 相关缓存占用。

## 一个直观判断

GPU 通常不怕“算得多”，更怕“算得零碎”。因此很多吞吐优化的核心都不是改变 Transformer 的数学定义，而是尽量把离散的小请求组织成 GPU 更擅长的大矩阵运算。

## 为什么和产品体验有关

吞吐优化直接影响三个体验指标：

- 首 token 延迟：用户多久看到第一段输出。
- 持续输出速度：用户感觉回复是不是顺畅。
- 高峰稳定性：并发上来时服务是否明显抖动或排队。

所以这不是纯底层细节，它会决定大模型产品在高并发场景下能不能稳定提供可接受的体验。
